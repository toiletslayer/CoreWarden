# Hackathon and submission context

CoreWarden was developed in the context of the AWS Agents for Humans hackathon.
Its submission story emphasized deterministic local monitoring, investigation
only when meaningful changes warrant it, and evidence for human judgment.
This context is project history, not a restriction to AWS or a promise of support
for every Core-derived node.

The original files remain at their existing paths to preserve references and
release packaging behavior:

- [Submission assets](../../submission-assets/README.md): presentation diagrams,
  screenshots, provenance, and capture notes from the submission checkpoint.
- [Recording plan](../../submission-assets/DEMO-RECORDING.md): competition video
  sequence, including explicitly labeled replayed results.
- [Judge quickstart](../../JUDGE-QUICKSTART.txt): originally judge-facing and still
  included by the Windows release builder; its operational steps remain useful.

Permanent project documentation lives in the root [README](../../README.md),
[architecture](../../ARCHITECTURE.md), [contributing guide](../../CONTRIBUTING.md),
and [security policy](../../SECURITY.md).
[Live validation](../../LIVE_VALIDATION.md),
[resilience validation](../../RESILIENCE-VALIDATION.md), the committed sanitized
[evidence](../../corewarden-evidence-live-healthy-success.json), and the
[synthetic harness guide](../../SYNTHETIC-MONITORING-DEMO.md) remain useful
technical records. Historical provider runs and test counts describe their
recorded checkpoints; they are not fresh validation of every release.
