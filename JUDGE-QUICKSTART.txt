CoreWarden v0.2.0 judge quickstart
=================================

FIRST PATH — cost-free acceptance (source checkout)
---------------------------------------------------

After installing the development checkout (`python -m pip install -e ".[dev]"`), run:

    .\scripts\judge_acceptance.ps1

This bounded command uses an ephemeral loopback JSON-RPC server, deliberately fake RPC
credentials, and a fake DiagnosisProvider. It contacts no real node and makes no OpenAI,
Bedrock, or other paid model request. It must report the exact healthy/degraded/deduplicated/
changed/recovered/unavailable sequence, exactly two fake-provider investigations, and clean
provider-visible privacy assertions. Full details: SYNTHETIC-MONITORING-DEMO.md.

SECOND PATH — packaged Windows GUI
----------------------------------

1. Extract the entire CoreWarden folder from CoreWarden-Windows-x64.zip. Do not move only
   CoreWarden.exe; its _internal directory is required.
2. Launch CoreWarden.exe. The executable is unsigned, so Windows SmartScreen may ask you to
   confirm that you trust it. The expected title is "CoreWarden — Read-only Node Health".
3. Choose OpenAI or Bedrock.
   - OpenAI: provide your own project API key. Saved keys use the current Windows user's
     Credential Manager; the ZIP contains no shared or maintainer-owned key.
   - Bedrock: authenticate your own AWS profile/session with Bedrock access. CoreWarden does
     not store AWS secrets.
4. Enter a running local Core-compatible node's URL and RPC username/password or cookie file.
   CoreWarden does not save RPC secrets. The 127.0.0.1:8337 default is for Bitcoin II; change
   it for other nodes or networks. See docs/BITCOIN-II-RPC-SETUP.md for Bitcoin II setup.
5. Select Test Provider, Test Node, then Run Diagnosis. Provider tests may make a small request
   billed to your account. Test Node is model-free. Run Diagnosis sends only locally filtered
   diagnostic evidence to the explicitly selected provider.
6. Optional monitoring is off by default. Healthy steady state, unavailability, recovery, and
   unchanged repeated degradation do not invoke AI. Only a new or materially changed degraded
   condition triggers one investigation.

Hard safety boundary
--------------------

CoreWarden exposes exactly getblockchaininfo, getnetworkinfo, getpeerinfo, and getchaintips,
all with empty parameters. It has no arbitrary RPC, wallet, transaction, restart, remediation,
shell, or filesystem tool. Peer-identifying and endpoint data is removed locally before model
access. RPC credentials, cookies, provider credentials, and wallet/private-key material are not
sent to the model by CoreWarden. Provider selection is explicit and never falls back silently.
