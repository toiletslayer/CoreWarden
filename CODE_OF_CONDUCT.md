# Code of conduct

CoreWarden welcomes people who want to improve the project, validate another node, report a bug, challenge an assumption, or suggest a different useful direction.

## Expected behavior

- Be respectful and discuss the work rather than attacking the person.
- Give technical disagreement room to be direct, evidence-based, and specific.
- Assume good faith when possible, while still calling out unsafe or incorrect behavior clearly.
- Do not harass, threaten, demean, dox, or deliberately expose another person's private information.
- Do not post live credentials, wallet secrets, private keys, seed phrases, private node endpoints, or other sensitive operational data.
- Keep contributions and issue discussions relevant enough that maintainers and contributors can act on them.

## Security and crypto-specific expectations

CoreWarden is intentionally read-only. Contributions must not quietly expand the project's authority into wallet access, transaction sending, destructive node operations, arbitrary shell execution, credential collection, or automatic remediation.

If a proposal changes that safety boundary, it must be raised explicitly and discussed before implementation.

Security vulnerabilities should be reported through the private process described in [SECURITY.md](SECURITY.md), not through a public issue containing exploit details or secrets.

## Enforcement

Repository maintainers may edit, hide, lock, or remove contributions and discussions that violate these expectations, and may restrict participation when necessary to protect contributors, users, or the project.

If you believe moderation was mistaken, contact the repository owner privately and explain the context.

The goal is simple: make it possible for people from different cryptocurrency communities and technical backgrounds to work on CoreWarden without turning the project into a hostile or unsafe place.
